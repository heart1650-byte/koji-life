# 糀Life 会員・注文データベース接続

実装済みの画面とSQL定義です。Supabaseへの接続とSMTP配信設定が完了するまで、実際の登録・個人情報保存・注文受付は開始しません。

## 接続手順

1. 運営者のSupabaseアカウントでプロジェクトを作成し、保管リージョンを選択します。
2. SQL Editorで `001-members-orders.sql` を一度実行します。再実行用のマイグレーションではありません。テーブル名の競合やエラーがあれば停止し、既存テーブルを削除しないでください。
3. Authenticationでメール認証を有効にします。メールのテンプレートには `{{ .Token }}` を記載し、6桁のコードを送る設定にします。サイトURLは https://heart1650-byte.github.io/koji-life/ 。パスワード・SNS認証はこの画面では使用しません。
4. 公開顧客向けのカスタムSMTPを設定し、迷惑メール対策・送信元認証・配信テストを行います。Supabase標準SMTPはチーム許可アドレス向けの制限があり、一般顧客向けの運用には使いません。SMTPパスワードはSupabase管理画面に入力し、GitHubやチャットに貼り付けないでください。
5. `member-config.json` にプロジェクトURLと publishable key（またはanon key）を設定し、配信テスト後に `emailDeliveryReady: true` にします。公開用の鍵のみを使い、service_role key・secret keyは絶対に掲載しません。
6. マイページで heart1650@gmail.com の認証を完了してから、SQL Editorで `002-bootstrap-admin.sql` を実行します。管理権限はブラウザから付与できません。
7. 管理画面で食品表示・セット構成・在庫を入力します。食品表示の未確認商品、在庫不足、販売準備中の商品はサーバー側で注文を拒否します。3点セットの在庫はセットとして確保済みの数を入力してください（単品の在庫を自動的には差し引きません）。
8. テスト用の顧客アカウントを2つ作り、会員情報の分離、配送先保存、注文と在庫減算、再送の重複防止、キャンセル時の在庫復元、銀行振込の承諾メールを確認します。
9. すべて確認後に `ordersReady: true` を設定し、管理画面で「注文受付を開始」を押します。銀行振込は手動で入金確認します。PayPay決済は未接続です。

## 保存する情報

会員プロフィール・配送先・お知らせ希望、商品・食品表示・在庫、注文・注文明細・購入時点の配送先と価格・食品表示、注文状態変更の管理履歴を保存します。メールは認証サービスで管理し、注文時は確認済みメールのみを使用します。

会員情報と注文は本人と管理者のみが参照できます。一般会員は価格・在庫・注文状態・他人の配送先を変更できません。注文はデータベースの関数で価格・在庫・食品表示を再確認します。失敗時は在庫減算も戻ります。

## 運用上の確認

注文状態は受付済み → 承諾・入金待ち → 入金確認済み → 発送済みです。承諾メール作成ボタンはメールアプリに下書きを表示し、自動送信しません。状態更新だけで契約案内メール・返金・発送は行われません。支払期限切れは管理者が確認してキャンセルします。退会・情報削除も本人確認のうえ運営者が対応します。配信事業者・保管リージョンが決まり次第、個人情報の取り扱いを更新してから公開受付を始めてください。

確認できていない原材料・アレルゲン・製造所・内容量・期限・栄養成分等は推測せず、実際の容器ラベルや製造記録に基づいて入力してください。Web表示は商品の容器包装の食品表示を代替しません。
